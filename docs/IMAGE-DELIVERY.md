# 이미지 전송 최적화

Task: COMPANY-IMAGE-DELIVERY-01. 기준 커밋9a3a7da. 회사 소개 시안의 이미지 전송량을 줄이되 원본과 화면 품질을 보존한다.

허용 변경: 원본 PNG를 읽어 무손실 WebP를 생성하는 빌드 스크립트, WebP 파일, HTML/CSS의 이미지 경로, 이미지 출처 기록의 변환 정보, 브라우저 검증 스크립트와 결과 문서. 원본 PNG 삭제·덮어쓰기, 크기 변경·자르기·색 변경·손실 압축은 하지 않는다. 외부 이미지 업로드나 유료 생성 요청도 하지 않는다.

완료 조건: 원본 SHA256 일치, 변환 전후 크기·채널·디코딩된 픽셀 바이트 동일, 실제 파일 크기 감소, 브라우저에서 변환된 파일을 사용하며 기존24개 시나리오 통과. 실제 전송 속도나 LCP 개선률은 측정 전 주장하지 않는다. 기존 운영 배포는 변경하지 않는다.

## 실행 결과

| 이미지 | PNG 원본(bytes) | WebP 전송본(bytes) |
| --- | ---: | ---: |
| atrium | 2,161,569 | 1,558,702 |
| operations | 2,371,914 | 1,699,954 |
| evidence | 1,968,204 | 1,414,198 |
| transition | 2,336,480 | 1,715,102 |
| 합계 | 8,838,167 | 6,387,956 |

2,450,211bytes, 27.72% 감소했다. 네 이미지 모두1672×941 크기와 디코딩된 픽셀 바이트가 동일하다. 각 원본·전송본의 해시와 픽셀 해시는 image-provenance.json에 기록했다. 원본은 그대로 보존했다. 이 수치는 파일 합계이며 페이지 전체 전송량이나 체감 속도 개선율이 아니다.

현재 HTML의8개 이미지 참조와 모바일 CSS 배경3개를 WebP로 연결했다. 최종 Edge/Playwright24개 조합이 통과했고 실제 currentSrc, 모바일의 계산된 CSS 배경 URL, 해당 이미지 HTTP200 및 image/webp 응답을 확인했다. 변환 전후375px·1440px 첫 화면 캡처는 SHA256이 같아 두 화면의 출력 파일도 동일했다.

독립 정적 검토에서 원본 덮어쓰기나 무손실 근거 오류는 발견되지 않았다. CSS 배경이 document.images 검사에 포함되지 않는 P3 검증 공백을 지적받아 배경 경로와 응답 검사를 추가하고 전체24개 조합을 재실행했다. 독립 검토자의 실행 결과로 주장하지 않는다.

## 재현 및 후속

Node와 Sharp를 사용할 수 있는 빌드 환경에서 `node scripts/encode-images.cjs`로 재현한다. 기존 설치를 NODE_PATH로 사용할 수 있다. 회사 웹사이트의 실행 시점에 Sharp를 설치하거나 실행할 필요는 없다. 패키지 또는 서버 구성은 이번 작업에서 변경하지 않았다.

추가 브라우저·실기기와 저속 네트워크의 체감 성능은 아직 검증하지 않았다. 더 작은 이미지가 필요하면 실제 표시 크기와 품질 기준을 정한 후 별도 작업으로 진행한다. 사이트 배포와 영상·실제 제품 화면 교체는 여전히 미완료다.
